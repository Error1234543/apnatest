## Findings requiring owner-side verification

### High priority — Supabase RLS and admin data access

- The checked-in `supabase/profiles.sql` defines self-only profile policies.
- The admin dashboard calls `is_prepgrid_admin()` and then reads profile rows directly from the browser client.
- The live database policies were not available in this repository review. Confirm that any administrator-wide profile SELECT policy is restricted to verified PrepGrid admins and that ordinary users can only read/update their own row.
- Audit every table, view, RPC, storage bucket, and exposed schema; checking only `profiles` is insufficient.
- Never expose a Supabase service-role/secret key in browser code.

### High priority — Telegram webhook configuration

- Both `functions/telegram-webhook.js` (Cloudflare Pages) and `netlify/functions/telegram-webhook.mjs` exist.
- Confirm which endpoint is actually configured as the Telegram webhook. Keep only the intended deployment path active operationally and ensure both copies do not drift.
- Current source uses a flat `TELEGRAM_ADMIN_IDS` allowlist. A separate superadmin permission tier and maintenance commands are not implemented in the inspected handlers.
- Verify `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_IDS`, and the Supabase server secret in hosting environment settings. Do not paste secret values into GitHub or chat.

### Medium priority — Route access behavior

- `_routes.json` includes all paths and has no exclusions.
- The middleware redirects HTML navigations (apart from login/callback paths) to Google sign-in. Confirm that this is intentional for all public study pages and static HTML content before changing route access.

### Medium priority — Edge protections

- Cloudflare WAF managed rules, rate limits, bot controls, and Turnstile server-side verification are dashboard/edge configuration tasks; they cannot be confirmed from these source files.
- Add rate limits to authentication/session and webhook endpoints using the active hosting platform's supported controls.
- Turnstile must be verified server-side; adding only a frontend widget is not protection.
