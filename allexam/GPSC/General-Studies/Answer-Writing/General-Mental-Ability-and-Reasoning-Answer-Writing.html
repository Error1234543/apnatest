Write a structured step-by-step solution for solving a mixed number series question commonly found in GPSC preliminary reasoning sections. Include the identification of the underlying pattern, the rule formulation, and verification using given terms.

Suggested points

  • Begin by listing all given terms with their positions indexed from 1
  • Compute first-order differences between consecutive terms
  • Compute second-order differences if first-order differences are not constant
  • Check for alternate-term patterns by splitting the series into odd and even positions
  • Test for multiplication-plus/minus patterns (e.g., ×2+1, ×3−2)
  • Test for square/cube-based patterns (n², n³, n²±k)
  • Formulate the general rule in words and apply it to predict the next term
  • Verify the derived rule against at least three given terms before concluding
  • Common traps: ignoring alternating patterns; stopping at one level of difference when a deeper pattern exists

Present a systematic answer-writing framework for blood-relation reasoning questions in GPSC exams. Cover single-line relations, multi-generation puzzles, and the most reliable notation method.

Suggested points

  • Introduce standard symbols: '+' for male, '−' for female, '×' for spouse, '→' for parent-to-child
  • Demonstrate translation of verbal statements into symbolic form step by step
  • For single-line relations: trace the chain from the reference person outward to the target person
  • For multi-generation puzzles: draw a family tree with generations clearly marked horizontally
  • Always mark known genders first, then eliminate impossible relations
  • Use a two-column method for long puzzles: left column for given facts, right for deductions
  • After constructing the tree, read off the required relation directly from the diagram
  • Common errors: confusing same-generation cousins with siblings; misreading 'mother-in-law' as 'mother'; missing hidden gender constraints
  • Conclude with a quick-verification sentence confirming no contradiction exists in the final tree

Write a complete model answer for a direction-sense problem involving multiple turns and distances. Explain the coordinate-method approach and how it eliminates visual confusion.

Suggested points

  • Set up a Cartesian coordinate system with starting point at origin (0, 0)
  • Assign directions: North = +y, South = −y, East = +x, West = −x
  • Plot each movement sequentially, updating coordinates after every leg
  • Record displacement values: x-coordinate for East-West net, y-coordinate for North-South net
  • Calculate final straight-line distance using Pythagorean theorem: √(x² + y²)
  • Determine final direction using tangent inverse: tan⁻¹(y/x), then map to compass quadrant
  • Always label intermediate points A, B, C… to avoid losing track
  • When the question asks direction from original position vs from last point, compute both separately
  • Common mistakes: sign errors when reversing direction; forgetting to combine movements along same axis; skipping the quadrant check for direction

Provide a structured answer for a linear and circular seating arrangement problem. Include a table-based representation method, constraint-handling sequence, and verification step.

Suggested points

  • Draw a blank diagram matching the shape described (line or circle) with numbered positions
  • List all constraints in shorthand notation before placing anyone
  • Start with the most restricted person or condition — it usually has the fewest placement options
  • For circular arrangements, fix one person's position to remove rotational symmetry, then place others relative to that anchor
  • Mark definite placements with solid labels and tentative placements with brackets
  • Use a elimination grid: rows for persons, columns for positions, cross out impossibilities
  • Apply negative constraints (e.g., 'A is not adjacent to B') by eliminating specific slots
  • Re-check every given condition against the final arrangement before answering the question
  • For questions asking 'who sits third to the left of X', count carefully in the correct direction
  • State the final arrangement in a compact row or circle notation as your conclusion

Write a model answer for a syllogism question using the Venn-diagram method. Demonstrate how to handle all four standard forms and correctly identify which conclusions logically follow.

Suggested points

  • Translate each statement into its standard categorical form: All A are B, No A is B, Some A are B, Some A are not B
  • Draw overlapping circles for each term, shading regions that are empty and marking 'X' for existential claims
  • For 'All A are B': shade the part of A that lies outside B
  • For 'No A is B': shade the entire intersection of A and B
  • For 'Some A are B': place an X in the overlap region of A and B
  • For 'Some A are not B': place an X in the part of A outside B
  • After drawing all statements together, test each conclusion by checking whether it holds in every valid diagram
  • Remember: if a conclusion is possibly true but not definitely true in all cases, it does not follow
  • Common trap: treating 'Some' as 'Only some' — Some A are B is compatible with All A being B
  • Conclude with a clear Yes/No for each conclusion with a one-line reason referencing the diagram

Present a structured answer-writing approach for coding-decoding questions involving letter shifting, reverse coding, and mixed pattern types found in GPSC reasoning sections.

Suggested points

  • First determine whether the code is based on position value (A=1, B=2…), reverse position (Z=1, Y=2…), or direct substitution
  • For letter-shifting codes: write the alphabet above the word and count steps forward or backward
  • For reverse-alphabet codes: pair A↔Z, B↔Y, C↔X and verify the pair mapping holds across all given letters
  • For number-letter mix codes: separate alphabetic transformation from numeric transformation and solve independently
  • For word-level reversal codes: check whether the entire word is reversed or individual segments are reversed
  • Always reconstruct the full rule from the given coded pair before applying it to the unknown word
  • When two examples are given, use them to cross-verify the identified rule to eliminate ambiguity
  • Common traps: confusing reverse-position coding with simple shift coding; missing a simultaneous two-rule system
  • Final step: encode the answer and confirm the output matches the length and structure expected

Write a complete model answer for an analogy question that requires identifying the relationship type, validating it across all options, and eliminating distractors systematically.

Suggested points

  • State the given pair and explicitly name the relationship type: definition, function, degree, part-whole, cause-effect, synonym/antonym, or sequence
  • Express the relationship as a clear sentence: 'A is the instrument used to measure B' or 'A is the capital of B'
  • Test this exact sentence against each option pair, substituting the option words
  • Eliminate options where the relationship is only superficially similar but structurally different
  • Beware of partial matches: an option may share one attribute but differ on the core relationship
  • For word-pair analogies involving letters/numbers, convert to the same domain before comparing
  • If two options seem equally valid, choose the one with the tighter, less ambiguous relationship
  • Record the chosen relationship in one precise sentence as the final justification
  • Common traps: selecting an option based on thematic similarity rather than relational identity; ignoring directionality (A:B ≠ B:A)

Provide a stepwise answer-writing method for ranking-and-position problems, including the formula for total participants and handling of overlapping ranks from both ends.

Suggested points

  • Write the standard formula: Total = Rank from left + Rank from right − 1
  • When people between two ranks are given, add the gap count to get the total occupied positions
  • For questions asking 'how many more to reach Xth rank', subtract current rank from target rank
  • When swapping positions occurs: new position of A = old position of B; use this to find total
  • Handle ambiguous cases: if the sum exceeds the total, the ranks overlap and you must recalculate using the gap method
  • For row-and-column combined problems (e.g., person's position in a grid), treat horizontal and vertical rankings independently
  • Verify by plugging the calculated total back into the original rank statements
  • Common errors: forgetting the '−1' in the total formula; double-counting the person who swapped; misreading 'between' as inclusive
  • End with a one-line confirmation showing the formula gives consistent results from both ends

Write a structured answer for a logical deduction question involving conditional statements (if-then, only-if, unless). Show how to derive valid conclusions and avoid common fallacies.

Suggested points

  • Convert every English conditional into symbolic form: P → Q, P ← Q, P ↔ Q
  • Recognize equivalent forms: 'Only if Q, P' translates to P → Q; 'Unless Q, P' translates to ¬Q → P
  • List all given conditions explicitly before attempting any inference
  • Apply Modus Ponens (P → Q, P ∴ Q) and Modus Tollens (P → Q, ¬Q ∴ ¬P) as the only universally valid direct rules
  • Reject invalid forms: affirming the consequent (P → Q, Q ∴ P) and denying the antecedent (P → Q, ¬P ∴ ¬Q)
  • Chain multiple implications together: if A → B and B → C, conclude A → C
  • For 'either-or' statements, list the two mutually exclusive cases and evaluate conclusions under each
  • When a conclusion cannot be determined with certainty, state 'insufficient data' rather than guessing
  • Final step: re-read the question to ensure the derived conclusion directly answers what was asked

Present a complete answer-writing framework for a data-sufficiency reasoning question in the GPSC exam. Explain how to evaluate each statement independently and in combination.

Suggested points

  • Restate the question as a specific value or yes/no query that must be answered definitively
  • Evaluate Statement 1 alone: determine whether it uniquely answers the question; if yes, mark sufficiency; if no or ambiguous, continue
  • Evaluate Statement 2 alone using the same criterion, independently of Statement 1
  • If neither statement alone is sufficient, combine both and test whether the joint information yields a unique answer
  • Remember: extra information in a statement does not make it insufficient — only non-uniqueness or contradiction matters
  • Watch for hidden assumptions: a statement may appear sufficient but allow multiple valid values
  • Use concrete numerical substitution to test whether different inputs produce different outputs under the given constraints
  • Map your finding to the standard five-option data-sufficiency code: (1) only 1 sufficient, (2) only 2 sufficient, (3) both needed, (4) each independently sufficient, (5) even together insufficient
  • Never carry over information from one statement to evaluate the other during independent assessment
  • Conclude with a one-sentence summary of why the chosen option is correct
