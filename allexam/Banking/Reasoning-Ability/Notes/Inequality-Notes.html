Inequality (असमिका) — Banking Reasoning Ability Complete Notes

BankingHindiNotes

1. असमिका क्या है? (What is Inequality?)

असमिका (Inequality) एक गणितीय संबंध है जो यह बताती है कि दो राशियाँ कितनी बड़ी या छोटी हैं, यह नहीं कि वे बराबर हैं या नहीं। जब दो राशियाँ बराबर होती हैं, तो हम '=' चिह्न का प्रयोग करते हैं, लेकिन जब वे बराबर नहीं होतीं, तो हम असमिका चिह्नों का उपयोग करते हैं। Banking के Reasoning में Inequality का मतलब होता है — दिए गए कथनों से निष्कर्ष निकालना कि कौन-सा संबंध (A > B, B < C आदि) सही है या नहीं।

मुख्य असमिका चिह्न:
- > (बड़ा) : A > B का अर्थ है "A, B से बड़ा है"
- < (छोटा) : A < B का अर्थ है "A, B से छोटा है"
- ≥ (बड़ा या बराबर) : A ≥ B का अर्थ है "A, B से बड़ा या बराबर है" (A ≥ B = A > B or A = B)
- ≤ (छोटा या बराबर) : A ≤ B का अर्थ है "A, B से छोटा या बराबर है" (A ≤ B = A < B or A = B)
- ≠ (असमान) : A ≠ B का अर्थ है "A, B के बराबर नहीं है"

Inequality questions में考生को अक्सर statements (कथन) और conclusions (निष्कर्ष) दिए जाते हैं, और उन्हें यह निर्धारित करना होता है कि दिया गया conclusion इन statements से logically follow करता है या नहीं।

2. Basic Rules of Inequality (प्रमुख नियम)

Inequality को solve करने के लिए निम्नलिखित आधारभूत नियमों को ध्यान से सीखना आवश्यक है:

Rule 1: Addition/Subtraction Rule — दोनों पक्षों में एक समान संख्या जोड़ने या घटाने से असमिका दिशा बदलती नहीं है।यदि a > b, तो a + c > b + c; यदि a < b, तो a - c < b - c।

Rule 2: Multiplication/Division Rule — यदि दोनों पक्षों में एक समान सकारात्मक संख्या से गुणा या भाग दिया जाए, तो असमिका दिशा नहीं बदलती। यदि a > b और c > 0, तो ac > bc। लेकिन यदि c < 0 (ऋणात्मक संख्या) से गुणा/भाग किया जाए, तो असमिका दिशा बदल जाती है। यदि a > b और c < 0, तो ac < bc।

Rule 3: Reversal Rule — यदि a > b, तो b < a।यदि a < b, तो b > a।

Rule 4: Transitive Property — यदि a > b और b > c, तो a > c।यदि a < b और b < c, तो a < c।यह सबसे महत्वपूर्ण नियम है जिनका उपयोग statements को जोड़ने के लिए किया जाता है।

Rule 5: Combining inequalities — यदि multiple statements हों, उन्हें एक साथ जोड़कर (merge करके) एक single inequality बनाया जा सकता है, بشرط कि common term हो।उदाहरण: A > B ≥ C, C < D ⇒ A > B ≥ C < D (यहाँ A और D का कोई सीधा संबंध नहीं है)।

Rule 6: Case when opposite signs मिलें — यदि two inequalities में common term के सापेक्ष signs एक ही दिशा में हों तो combine करना simple है, लेकिन यदि Signs opposite हों (जैसे A > B < C), तो कोई definite conclusion नहीं निकाला जा सकता बिना further information के।

3. Types of Questions: Follows vs Does Not Follow (प्रश्न प्रकार)

Banking exams में Inequality के दो मुख्य प्रकार के प्रश्न पूछे जाते हैं:

Type 1: Conclusion Follows / Does Not Follow — इसमें कुछ statements दिए जाते हैं और कुछ conclusions,考生को बताते हैं कि कौन-सा conclusion statement से logically follows करता है।यदि conclusion की दिशा statement से मेल खाती है और relation definite है, तो वह follows करता है।

Type 2: Pairs of Inequalations — कभी-कभी考生को दो statements दी जाती हैं जिनसे यह पता लगाना होता है कि कौन-सा pair true है या false है।

Important distinction — "Follows" का मतलब है कि दी गई information के आधार पर conclusion सदैव सत्य है। यदि किसी case में conclusion false भी हो सकता है, तो वह "does not follow" होता है, भले ही कुछ cases में वह true भी लगे।

For example: Statement: X > Y ≤ Z। Conclusion: X > Z।इसका उत्तर NO है क्योंकि Y के कारण relation ambiguous है — यदि Y छोटा है तो X > Z संभव है, यदि Y बड़ा है तो X < Z भी संभव है। ऐसा relation "Neither follows nor does not follow" नहीं कहलाता — बल्कि "does not follow" कहलाता है क्योंकि यह सदैव सत्य नहीं है।

4. Solving Method: Combine and Check (समाधान विधि)

Inequality problems को solve करने की systematic method निम्नलिखित है:

Step 1: Statements को एक linear form में लिखें — सभी variables को एक line में arrange करें ताकि common terms apparent हो जाएँ।

Step 2: Symbol check करें — प्रत्येक pair में relation देखें। यदि relation exists है (जैसे > या ≥), तो उसे mark करें।

Step 3: Direction match करें — यदि दोनों terms के बीच arrows same direction हैं (जैसे सभी left-to-right → →), तो relation मिल सकता है। यदि directions opposite हैं (→ ←), तो definite relation नहीं निकाल सकते।

Step 4: Conclusion check करें — प्रत्येक conclusion को original statement से match करें। यदि arrow direction and symbol match करता है, तो conclusion true है।

Example: Statement: P ≥ Q < R = S ≤ T
Conclusion 1: P > R → False (क्योंकि P ≥ Q < R means direction changes at Q, so no direct relation between P and R)
Conclusion 2: R = S → True (directly given)
Conclusion 3: Q < T → True (Q < R = S ≤ T, so Q < T via transitive property)

Short Trick — "Arrow Method": हर variable से arrows निकालें जो right side की ओर हैं। अगर एक arrow है, तो symbol उसी direction में दिखता है। अगर दो arrows मिलते हैं (→→), तो symbol maintain रहता है। अगर arrows reverse होते हैं (→←), तो कोई relation नहीं बनता।

Common symbols mapping:
- Two same direction arrows (→ →): relation = given symbols maintain
- One arrow (→ only): direct relation exists
- Opposite arrows (→ ←): NO relation possible

5. Symbol Code / Substitution Questions (प्रतीक कोड प्रश्न)

कभी-कभी Banking exams में symbol substitution type के प्रश्न पूछे जाते हैं, जहाँ考生को different symbols (like @, #, $, %) दी जाती हैं जिनका मतलब अलग-अलग होता है, और考生को statements के आधार पर conclusions find करने होते हैं।

उदाहरण के लिए:
- 'A @ B' का अर्थ है 'A < B'
- 'A # B' का अर्थ है 'A ≤ B'
- 'A $ B' का अर्थ है 'A = B'
- 'A * B' का अर्थ है 'A ≥ B'
- 'A % B' का अर्थ है 'A > B'

इस तरह के प्रश्नों में考生的को पहले symbols को standard inequality signs में convert करना होता है, फिर same method से solve करना होता है।

Strategy: पहले सभी statements को decode करके standard form में लिखें। फिर step 1-4 का use करें जैसे ऊपर बताया गया है।

यह section तब apply होता है जब考生को explicitly symbol substitution के प्रश्न दिए जाते हैं।

6. Common Mistakes to Avoid (कॉमन गलतियाँ)

Inequality में考生ओं द्वारा अक्सर की जाने वाली गलतियाँ:

Mistake 1: Reverse arrow assumption — जब two inequalities combine होते हैं लेकिन arrows direction बदलते हैं,考生 often incorrectly assume relation holds. Example: A > B और B < C ⇒考生 कहते हैं A > C — यह गलत है।

Mistake 2: Ignoring equality cases — ≥ और ≤ में equal case शामिल होता है।考生 इसे overlook करते हैं। Example: A ≥ B और B ≥ C ⇒ A ≥ C है, न कि A > C।

Mistake 3: Treating opposite direction as valid — जब arrows opposite facing हैं (→ ←),考生 mistakenly try to establish a relation. Actually NO relation can be drawn.

Mistake 4: Not checking all conclusions — कई times考生 एक conclusion check करके stop कर देते हैं जबकि multiple conclusions पूछे गए हैं।

Mistake 5: Confusing 'neither/nor' with 'both' — यदि conclusion A > B और B < A दोनों wrong हैं, तो考生 कहते हैं 'both are true' — यह भी गलत है।

Mistake 6: Forgetting that 'Either/Or' condition लागू होता है — यदि兩個 conclusions में एक correct direction है और दूसरा reverse direction है, और they cover all possibilities, तो answer 'either/or' हो सकता है।

Mistake 7: Jumping to conclusions without combining —考生在 statements को बिना combine किए ही direct relation मान लेते हैं।

Mistake 8: Misreading symbols — > और ≥, < और ≤ में confusion करना।कभी-कभी考生 > को ≥ पढ़ लेते हैं।

Quick prevention tip: हर बार statement को diagram या line में write करके visually check करें।

7. Either-Or Cases (द्वैध या स्थिति)

Either-Or case तब applies होता है जब two conclusions में से कोई एक definitely true हो सकता है, लेकिन दोनों একসাথে true नहीं हो सकते।

Conditions for Either-Or:
1. दोनों conclusions में same variables हों।
2. दोनों conclusions में opposite signs हों (एक > और दूसरा <)।
3. Variableों के बीच arrow direction mismatch हो (one is A > B, other is A < B)।
4. Statement में कोई third variable न हो जो relation को break कर दे।
5. Variableों के बीच direct relation exist करता हो (combine होने योग्य हो)।

Example: Statement: M > N, N ≥ O
Conclusion 1: M > O
Conclusion 2: M < O

यहाँ M > N ≥ O ⇒ M > O or M < O — दोनों possible हैं, लेकिन दोनों एक साथ नहीं हो सकते। इसलिए answer है: Either 1 or 2 follows।

Another Example: Statement: P ≥ Q < R
Conclusion 1: P > R
Conclusion 2: P < R
यहाँ P > R और P < R दोनोंpossible हैं, लेकिन definite relation नहीं है क्योंकि Q के कारण direction बदलता है। तब answer "Neither follows" होगा, na ki either/or।

Point to remember: Either-Or तभी work करता है जब two variables के बीच direct combined path exists हो।

8. Worked Examples (विस्तृत उदाहरण)

Example 1: Statement: A > B ≤ C = D ≥ E
Conclusions:
I. A > C
II. B < D
III. C > E
IV. A > E

Solution:
Arrow mapping: A →(>) B ←(≤) C =(=) D ≥(≥) E
Check I: A > B ≤ C → direction changes at B, so no relation A vs C → False
Check II: B ≤ C = D → B < D or B = D, but B ≤ D, so B < D follows → True
Check III: C = D ≥ E → C > E or C = E, so C > E not always true → False (could be equal)
Check IV: A > B ≤ C = D ≥ E → multiple direction changes, no relation between A and E → False
Answer: Only II follows

Example 2: Statements: P ≥ Q, Q > R, R ≤ S
Conclusions:
I. P > R
II. Q > S
III. P ≥ S
IV. Q = S

Solution:
P ≥ Q > R ≤ S
Check I: P ≥ Q > R → P > R always true → True
Check II: Q > R ≤ S → direction changes at R, no relation Q vs S → False
Check III: P ≥ Q > R ≤ S → same reason, no relation P vs S → False
Check IV: Q > R ≤ S → Q = S possible? No direct link → False
Answer: Only I follows

Example 3 (Either-Or):
Statement: X ≥ Y < Z
Conclusion I: X > Z
Conclusion II: X < Z
Solution: X ≥ Y < Z → direction changes at Y, so neither X > Z nor X < Z is definite. Neither follows।

9. Shortcut Tricks & Quick Decision Tree (शीघ्र समाधान तकनीक)

Quick Trick — Symbol Check Table:

| Symbol | Meaning |
|--------|----------|
| > | strictly greater |
| < | strictly lesser |
| ≥ | greater than or equal |
| ≤ | lesser than or equal |
| = | equal |
| ≠ | not equal |

Quick Decision Steps:
1. सभी statements को एक line में align करें।
2. हर pair के बीच arrow count करें।
3. If arrows face same direction → compare symbols directly.
4. If one arrow faces opposite → no relation (除非equal case covers it)。
5. Mark each conclusion TRUE/FALSE/Neither.

Mnemonic: "SAAC" — Same Arrow Always Combine, Opposite Arrow Absolutely Cancelled.

Another useful shortcut — "Complementary Pair Check":
यदि conclusion में same pair repeated opposite relation हो (जैसे A > B और A < B), और दोनों possible हों, तो "Either/Or" check करें।

Speed tip: हर statement को solve करते समय 10-15 seconds से कम लगे।

10. Exam Weightage & Practice Tips (परीक्षा में महत्व और अभ्यास टिप्स)

Banking exams (IBPS PO/Clerk, SBI PO/Clerk, RBI Grade B) में Inequality से अक्सर 2-4 questions पूछे जाते हैं, जो 2-4 marks के बराबर होते हैं। ये questions relatively easier हैं और accurate practice से score करने योग्य होते हैं।

Practice Tips:
- Daily at least 5-10 inequality problems solve करें।
- Arrow method और symbol check table याद रखें।
- Either-Or conditions के लिए विशेष attention दें — अक्सर考生 इन्हें miss कर देते हैं।
- Speed increase के लिए combination practice करें — एक ही statement से multiple conclusions check करें।
- Mock tests में inequality section solve करने का time 10-15 minutes से कम रखें।
- गलतियों का register बनाएं — हर गलत question को analyze करें कि nào mistake हुई थी।
- Symbol substitution type questions के लिए extra practice करें।

High-Yield Focus Areas:
- Transitive property (Rule 4) पर most emphasis है।
- Either-Or conditions frequently tested हैं।
- ≥ और ≤ के साथ equality cases को properly handle करना आता होना चाहिए।
- Multiple statements को एक लाइन में जोड़ने की skill develop करें।

Important facts

  • Inequality में ≥ और ≤ symbols में equal case included होता है, > और < में exclusive होता है
  • Transitive property (a>b, b>c ⇒ a>c) सबसे महत्वपूर्ण rule है inequality solving का
  • Opposite arrows (→←) के बीच कोई definite relation नहीं बना सकते
  • Same direction arrows (→→) के बीच symbols maintain रहते हैं
  • Either-Or condition तब लागू होती है जब दो conclusions opposite directions में हों और दोनों possible हों
  • Multiplication/division by negative number से inequality direction reverse हो जाती है
  • Symbol substitution questions में पहले decode करके standard form में convert करें
  • Banking exams में Inequality से 2-4 questions typically पूछे जाते हैं
  • SAAC mnemonic: Same Arrow Always Combine, Opposite Arrow Absolutely Cancelled
  • Confidence building के लिए daily practice mandatory है

Formulas and relationships

a > b और b > c ⇒ a > c (Transitive Property — Basic Rule)
a < b और b < c ⇒ a < c (Transitive Property — Basic Rule)
a ≥ b और b ≥ c ⇒ a ≥ c (Transitive with Equality)
a ≤ b और b ≤ c ⇒ a ≤ c (Transitive with Equality)
a > b और c > 0 ⇒ ac > bc (Multiply by positive — direction unchanged)
a > b और c < 0 ⇒ ac < bc (Multiply by negative — direction REVERSED)
a > b ⇒ b < a (Reversal Rule)
a ≥ b ≥ c ⇒ a ≥ c (Chain Inequality — Multiple combine)
If A > B < C ⇒ NO relation between A and C (Opposite arrows — invalid)
If A ≥ B ≤ C ⇒ A और C के बीच NO direct relation (Direction change)

Common mistakes

  • Reverse arrow assumption: A > B < C से的考生 mistakenly conclude A > C — यह गलत है क्योंकि direction बदलती है
  • Ignoring equality: A ≥ B और B ≥ C से考生 A > C say करते हैं, जबकि A ≥ C correct है (equal case miss हुआ)
  • Misreading symbols: > को ≥ और < को ≤ पढ़ लेना — यह बहुत common गलती है
  • False either/or: जब variables के बीच opposite arrows हों (→ ←),考生 either/or कह देते हैं — wrong, यह neither है
  • Jumping to conclusion without combining:考生 statements को merge किए बिना ही direct relation मान लेते हैं
  • All conclusions को एक साथ check न करना:multiple conclusions में से एक check करके stop कर देना
  • Missing the ≥ / ≤ subtlety: A ≥ B का मतलब A > B OR A = B,考生 इसे अक्सर A > B समझ लेते हैं
  • Not recognizing complementary pairs: जहाँ दोनों conclusions opposite हों और cover all cases, वहां either/or miss करना
